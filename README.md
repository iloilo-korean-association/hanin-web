# 일로일로 한인회 웹앱 — 로컬 프로토타입

**목업이 아닙니다.** SQLite 파일에 실제 데이터가 들어가고, 실제로 계산되고, 실제로 저장됩니다.
계정을 하나도 만들지 않고(구글·Vercel·Supabase 전부 미가입), PC 한 대에서 전부 돌아갑니다.

---

## 1. 실행 — 명령 3줄

터미널에서 이 폴더(`06_웹앱`)로 들어간 뒤:

```bash
npm install
npm run db:reset
npm run dev
```

브라우저에서 **<http://localhost:3000>** 을 엽니다.

- `npm install` — 필요한 패키지를 받습니다 (1~2분, 인터넷 필요. 이후로는 오프라인에서도 돕니다)
- `npm run db:reset` — 데이터베이스를 새로 만들고 **시드 데이터**를 넣습니다
  (회원 60명 · 임원 5명 · 거래 119건 · 회비고지 60건 · 발송함 36통 …)
- `npm run dev` — 개발 서버를 켭니다. `Ctrl+C` 로 끕니다

> 처음부터 다시 보고 싶으면 `npm run db:reset` 을 다시 실행하십시오. 데이터가 초기 상태로 돌아갑니다.

**필요 환경:** Node.js 20.9 이상 (이 PC 에서 v24.16.0 으로 확인). Docker·데이터베이스 설치 불필요.

## 2. 무엇부터 보시면 되는지

### ① 공개 화면 — 로그인 없이 누구나

| 주소 | 무엇 |
| --- | --- |
| <http://localhost:3000/> | 홈 |
| <http://localhost:3000/ledger> | **공개 회계** — 지출은 건별 전액 공개, 수입은 집계만 |
| <http://localhost:3000/biz> | 업소 안내 — 임원 이해관계 배지가 상시 붙습니다 |
| <http://localhost:3000/sos> | 긴급 연락처 |
| <http://localhost:3000/join> | 회원 가입 |

주소창에 직접 쳐서 들어가도, 북마크해도, 뒤로가기를 눌러도 정상 동작합니다.
**이것이 Apps Script 판에서 안 되던 것입니다.**

### ② 개발용 화면 — 대표가 여러 역할을 오가며 보는 곳

| 주소 | 무엇 |
| --- | --- |
| <http://localhost:3000/dev/login> | **빠른 로그인** — 회장·총무·감사를 클릭 한 번으로 전환 |
| <http://localhost:3000/dev/outbox> | **메일 발송함** — 나갈 메일을 그대로 봅니다 |

> `/dev/*` 는 개발 중에만 열립니다. 실제 서비스(`NODE_ENV=production`)에서는 **404** 입니다.

### ③ 꼭 해 보셔야 할 3가지 (5분)

1. **감사 계정으로 쓰기를 시도해 보십시오.**
   `/dev/login` → 감사 계정 선택 → 수납·지출 화면으로 들어갑니다.
   버튼이 회색으로 비활성되고 *왜* 못 누르는지가 함께 표시됩니다.
   그리고 **버튼을 우회해서 직접 요청을 보내도 서버가 거부합니다** — 화면에서 숨기는 것은
   통제가 아니라는 원칙을 코드로 강제했습니다.

2. **메일이 어떻게 나가는지 보십시오.**
   `/dev/outbox` 에서 영수증·독촉·환영 메일이 실제 본문 그대로 보입니다.
   시드에 36통이 들어 있습니다. 회원용 링크는 **"링크 열기"** 를 누르면 그대로 들어가집니다
   (실제 메일 발송 없이 회원 화면을 체험).

3. **카톡 썸네일 카드를 확인하십시오.**
   <http://localhost:3000/opengraph-image> 를 열면 1200×630 카드가 나옵니다.
   한글이 제대로 그려집니다. Apps Script 로는 이 태그 자체를 넣을 수 없었습니다.

### ④ 종이로 뽑아 보십시오

회계 화면에서 `Ctrl+P`. 네비게이션·버튼은 사라지고 표만 A4 에 정리돼 나옵니다.
정전·태풍이 잦아 종이 결산이 실제로 필요합니다.

## 3. 로그인 정보

**임원 비밀번호:** `npm run db:reset` 실행 시 콘솔에 한 번 출력됩니다. 고정하려면 `SEED_PASSWORD` 환경변수를 주십시오.
이메일은 `/dev/login` 화면의 임원 목록에 있습니다.

실제 운영에서는 시드가 넣은 이 비밀번호를 반드시 바꿔야 합니다.
`/dev/login` 은 비밀번호를 묻지 않으므로, 화면을 둘러보실 때는 그쪽이 편합니다.

**회원**은 비밀번호가 없습니다. 메일로 받은 **매직링크**(`/me/<토큰>`)로 들어갑니다.
`/dev/login` 아래쪽 또는 `/dev/outbox` 에서 바로 누를 수 있습니다.

## 4. 이 프로토타입이 지키는 규칙

### 회계 불변식 — 이 시스템의 존재 이유

| | 규칙 | 어떻게 강제되나 |
| --- | --- | --- |
| **I1** | 거래는 삭제되지 않는다 | VOIDED 처리 + 역분개만. **삭제 경로 자체를 만들지 않았습니다** |
| **I2** | 영수증번호에 결번이 없다 | 회계연도별 순번을 **트랜잭션 안에서** 채번 |
| **I3** | 증빙 없이 POSTED 불가 | 증빙이 없으면 DRAFT 로 떨어지고 공개 집계에 안 잡힙니다 |
| **I4** | 현금 임계 초과는 2인 확인 | 확인자 ≠ 입력자를 **서버가** 검사 |
| **I5** | 마감된 회계연도는 불변 | 마감 후 쓰기 거부 |
| **I6** | 개시잔액 = 전기 마감잔액 | 시드 검산에서 매번 확인 |

시드를 넣을 때마다 위 항목을 스스로 검산하고 결과를 터미널에 출력합니다.
`npm run db:reset` 마지막 줄에 **"검산 전부 통과"** 가 떠야 정상입니다.

### 개인정보 (필리핀 DPA RA10173 · 한국 PIPA)

- **지출은 건별 전액 공개** — 일자·과목·금액·수취인·적요·증빙유무·이해관계 배지
- **수입은 집계만** — 누가 얼마 냈는지는 공개하지 않습니다. 미납자 낙인은 법 위반 소지가 있습니다
- **공개 화면에 회원 실명 0건** — 시드 검산이 이 조건을 매번 확인합니다
- 여권번호·ACR I-Card·주민등록번호는 **수집하지 않습니다**

### 이해상충

대표가 일로일로에서 여러 사업을 운영하고 배우자가 로펌을 합니다. 이 사실을 숨기지 않고
**시스템이 먼저 드러내도록** 만들었습니다.

- 업소 안내·공개 회계에 이해관계 배지 + 지분율 상시 노출
- 지출 상대방이 임원 관련 업체면 자동 플래그 → **해당 임원의 승인 버튼 비활성(회피)**
- 이름 대조는 NFKC 정규화 + 화이트리스트 방식입니다.
  제로폭 공백·자모 분리·전각 부호로 우회하려는 시도를 시드 검산에서 4/4 탐지합니다

## 7. 자주 막히는 곳

**포트 3000 이 이미 쓰이고 있다고 나옵니다**
다른 프로그램이 쓰고 있습니다. `npm run dev -- -p 3001` 로 다른 포트를 쓰십시오.

**`npm run db:reset` 이 안 됩니다 / 데이터가 이상합니다**
`prisma/dev.db` 파일을 지우고 다시 실행하십시오. 파일 하나가 데이터베이스 전부입니다.

**`SESSION_SECRET` 오류가 납니다**
`.env` 파일이 없는 경우입니다. `.env.example` 을 복사해 `.env` 로 만들고, `SESSION_SECRET` 에
32자 이상의 아무 문자열이나 넣으십시오.

**og:image 에 한글이 안 나오고 네모로 나옵니다**
카드 생성기가 시스템 한글 폰트를 찾지 못한 경우입니다. Windows 에서는
`C:\Windows\Fonts\malgun.ttf` 를 자동으로 씁니다. 다른 환경이면 `.env` 에
`OG_FONT_PATH` 로 `.ttf`/`.otf` 파일 경로를 지정하십시오 (WOFF2 는 안 됩니다).
못 찾으면 영문 카드로 자동 대체되며, **빌드는 깨지지 않습니다.**

## 8. 이 프로토타입의 목적과 한계

**목적 두 가지**

1. 대표가 "pialms 처럼 제대로 된 제품인지" 를 눈으로 판단하는 것
2. 프로덕션 이식 견적(13~16주)이 맞는지 실측하는 것

**지금 하지 않는 것 (의도적으로)**

- **실제 메일 발송을 하지 않습니다.** 발송함에 기록만 합니다 (외부 계정 0개 원칙)
- **인터넷에 배포되어 있지 않습니다.** 이 PC 에서만 돕니다
- 파일 업로드(증빙 사진)는 URL 문자열로만 다룹니다. 실제 저장소는 프로덕션 과제입니다
- DB 는 SQLite 입니다. 프로덕션은 Postgres 예정이며,
  **enum 을 쓰지 않고 문자열 + zod 검증으로 통일**해 두었으므로 옮길 때 스키마를 고칠 일이 없습니다

## 9. 개발자에게 (다음 사람이 읽을 것)

### 인증 3계층

| 계층 | 방식 | 관문 |
| --- | --- | --- |
| 공개 | 인증 없음 | — |
| 회원 | 매직링크 `/me/[token]` | `requireMember(token)` |
| 임원 | 이메일 + 비밀번호(bcrypt) + httpOnly 세션 쿠키 | `requireOfficer({...})` |

**쓰기 경로는 예외 없이 `guard.ts` 를 첫 줄에서 통과해야 합니다.**

```ts
"use server";
import { requireOfficer } from "@/lib/guard";

export async function 수납기록(formData: FormData) {
  const me = await requireOfficer({
    permissions: ["입력권"],
    write: true,            // ← 감사 계정을 서버에서 거부
    screen: "수납 기록",
  });
  // me.officerId 를 입력자로 남긴다
}
```

세션 쿠키에는 **신원(임원ID)만** 들어 있습니다. 직책·권한·승인한도는 넣지 않았습니다 —
넣으면 총무가 감사로 바뀌어도 쿠키가 만료될 때까지 옛 권한이 살아 있게 됩니다.
`requireOfficer()` 가 요청마다 `Officer` 테이블을 다시 읽습니다.

### 주의: `npm run db:reset` 을 AI 에이전트가 실행하면 막힙니다

Prisma 6.19 부터 `db push --force-reset` 은 AI 코딩 도구가 실행할 때 사용자 동의를 요구하고
중단합니다(운영 DB 파괴 방지 장치). **사람이 직접 터미널에서 실행하면 정상 동작합니다.**
에이전트로 작업 중이라면 `npx prisma db push` + `npx tsx prisma/seed.ts` 로 나눠 실행하십시오.

### 지켜야 할 코드 규약

- TypeScript strict. `any` 금지
- 입력 검증은 zod. 클라이언트 검증만 믿지 않습니다
- `dangerouslySetInnerHTML` 금지. HTML 미리보기는 `<iframe srcDoc sandbox="">` 로 합니다
  (`/dev/outbox` 참고)
- 외부 CDN·웹폰트 금지. 시스템 폰트 스택만 씁니다
- 표는 반드시 `<TableScroll>` 안에 넣습니다. 모바일에서 본문이 가로로 밀리면 안 됩니다
